================================================================================
MIDDLEWARE SALES EXPORT (external consumers — same JSON format on all routes)
================================================================================

These routes READ synced POS sales from Supabase. SCPGT middleware on outlet PCs
does NOT call these — it pushes sales into Supabase directly.

Outlet mapping (middleware_sales_api_profile in Supabase):

  Till 1   648e949d-8648-4c43-80d4-f08feb7bdd04  → profile: till
  Till 2   a655b0a1-a37a-43d6-aa55-7f97377b2660  → profile: till
  Quick Corner  a406fede-7aab-4473-8e9f-ff645267466f  → profile: quick_corner

--- Till 1 + Till 2 (one shared route) ---

GET  https://aftertentransfers.app/api/outlet-middleware-sales/tills
     Both Till 1 and Till 2 in one response. Query: since, until, limit
     (default 1000, max 5000). Optional outletId to filter one till only.

--- Quick Corner (separate route) ---

GET  https://aftertentransfers.app/api/outlet-middleware-sales/quick-corner
     Quick Corner only. Query: since, until, limit.

--- Legacy / all outlets ---

GET  https://aftertentransfers.app/api/outlet-middleware-sales
     All middleware outlets. Query: outletId, since, until, limit,
     profile (till | quick_corner).

Response fields (all routes): api_format_version (2), since, until, limit,
sales_count, grouping ("by_outlet"), middleware_api_profile, outlet_ids,
outlet_summaries[], sales[] (each sale has outlet_uuid, lines, payment_methods, etc.).

================================================================================
MIDDLEWARE MONITORING & POS SYNC
================================================================================

GET  https://aftertentransfers.app/api/middleware-status
     Middleware heartbeat + last catalog sync per POS outlet.

GET  https://aftertentransfers.app/api/middleware-catalog-schedule
PUT  https://aftertentransfers.app/api/middleware-catalog-schedule
     Global scheduled POS catalog sync (PUT body: { scheduled_at }).

GET  https://aftertentransfers.app/api/pos-sales
     POS orders from Supabase orders table.
     Query: outletId, since, until, limit (default 500, max 2000),
     branchId, sourceEventId, sourceEventPrefix,
     includeSales (or include=sales) to also return outlet_sales rows.

GET  https://aftertentransfers.app/api/pos-sync-alert
     POS mapping mismatches + sync failures (last 7 days).

POST https://aftertentransfers.app/api/catalog/sync-pos-catalog
     Bulk upsert catalog items/variants from JSON rows (backoffice import).

POST https://aftertentransfers.app/api/catalog/request-pos-catalog-sync
     Queue on-demand POS catalog sync for outlet(s).
     Body: { outlet_ids[], outlet_options?, scheduled_at? }.

POST https://aftertentransfers.app/api/catalog/cancel-offline-pending-sync
     Cancel pending offline catalog sync events.

================================================================================
OUTLETS & WAREHOUSES
================================================================================

GET  https://aftertentransfers.app/api/outlets
     List outlets.
     Query scope: selling | pos-deductions | middleware | catalog-sync | heartbeat
     (omit scope for all).
     Each outlet includes middleware_sales_api_profile and middleware_sales_api_path
     when applicable (till → /api/outlet-middleware-sales/tills,
     quick_corner → /api/outlet-middleware-sales/quick-corner).

PUT  https://aftertentransfers.app/api/outlets
     Update outlet default_sales_warehouse_id.
     Body: { updates: [{ id, default_sales_warehouse_id }] } or single { id, ... }.

GET  https://aftertentransfers.app/api/outlet-warehouses
     Outlet ↔ warehouse links.
     Query: outlet_id, scope (outlet | pos-deductions),
     stocktake=1 or for_stocktake=true (with scope=outlet).

GET  https://aftertentransfers.app/api/warehouses
     List warehouses.
     Query: include_inactive (1|true), scope (outlet | hub), outlet_id,
     locked_id / fromLockedId / lockedWarehouseId (repeatable).

GET  https://aftertentransfers.app/api/operators
     Operator directory (supervisors from Auth metadata).

     POS menu groups.

GET  https://aftertentransfers.app/api/catalog/changes
     Catalog change feed (products, variants, menu groups).
     Query: since (ISO), until (ISO), change_type (comma-separated),
     entity_type (item|variant|menu_group), entity_id, sku, limit (default 100, max 1000).
     Change types: product_added, product_deleted, product_name_updated,
     product_price_updated, product_cost_updated, product_updated,
     variant_added, variant_deleted, variant_name_updated, variant_price_updated,
     variant_cost_updated, variant_updated, menu_group_added, menu_group_deleted,
     menu_group_name_updated, menu_group_updated.
     Poll with ?since=<latest_at> for near-real-time updates.

NOTES
================================================================================

- Auth: backoffice APIs expect a logged-in Supabase session; middleware sales
  export routes are public GET (no auth in route handler).
- Default date window for sales export APIs: last 7 days when since/until omitted.
- Till 1 & Till 2 share one export URL (/tills); filter with outletId when needed.
- Quick Corner uses a separate URL (/quick-corner) with identical response shape.
