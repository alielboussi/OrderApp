Firestore sync check — Till 1
=============================

Outlet ID: 648e949d-8648-4c43-80d4-f08feb7bdd04

Run on your dev machine (PowerShell)
------------------------------------

  cd C:\Projects\Afterten\CHECK SYNC
  node firestore-count.cjs

Requires:
  - Node.js installed
  - Firebase credentials at: C:\Projects\Afterten\secrets\afterten-firebase-adminsdk.json
  - firebase/functions dependencies installed (npm install in firebase/functions)

What to compare
---------------

Run BOTH checks and compare the numbers:

  1. Till 1 SSMS  →  mintpos-sync-status.sql
  2. Dev machine  →  node firestore-count.cjs

| MintPOS column              | Firestore        | Fully synced when        |
|-----------------------------|------------------|--------------------------|
| exportable_bills_with_lines | Bills count      | Both numbers are EQUAL   |
| pending_bills               | —                | pending_bills = 0        |
| processed_bills             | —                | processed = exportable   |

Example (not yet synced):
  MintPOS exportable: 23854
  MintPOS pending:    2359
  Firestore bills:    20815
  → Still uploading (20815 / 23854)

Example (fully synced):
  MintPOS exportable: 23854
  MintPOS pending:    0
  MintPOS processed:  23854
  Firestore bills:    23854
  → SYNC COMPLETE

If pending stays at 0 but Firestore count is lower than exportable
------------------------------------------------------------------

Some bills may be marked Processed in MintPOS but missing from Firestore.
Regenerate and run the reconciliation script:

  cd C:\Projects\Afterten\firebase\functions
  node ../scripts/generate-requeue-missing-sql.cjs --out ../scripts/till1-requeue-missing.sql

Stop SCPGT on Till 1 before running the requeue SQL, then start SCPGT again.

If pending does not drop over time
----------------------------------

SCPGT may be blocked on a failed bill. Check the SCPGT log on Till 1 or
Firestore outlet_heartbeats for blockedBillId / blockedSourceEventId.
